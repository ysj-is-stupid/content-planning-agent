# 36 项设计审查与处理结论

更新：2026-11-05。审查对象为旧版《技术选型分析.md》第 11–12 节；处理结果写入本目录 v2 需求与设计。结论是文档层面的判断，不代表已经用代码解决。

标记含义：**存在**＝旧稿缺少必要机制；**部分成立**＝已有原则或首版边界，但不足以直接实现/验收；**原表述不成立**＝旧稿明确写过或要求超出本题，仍可改善表达。

## 一、业务语义

1. **部分成立：预算口径。** 旧稿 11.6 已建议活动预算单独约束、工具免费，不能说完全未定义；收费扩展确实没定。v2 改成唯一总预算口径，包含已结算模拟工具费与最终活动报价，沉没成本不退。
2. **存在：版本触发。** v2 不用“微调阈值”，任何规范化业务规格变化都生成不可变版本；显示元数据另存。
3. **存在：复用判定。** v2 分检索、脚本、部分脚本、报价定义依赖指纹，缺少兼容规则时不复用。
4. **部分成立：部分成功。** 旧稿已经要求保留真实产物，不冒充全成功；是否能估算/保存与计费尚缺。v2 明确 partial 不可估算/保存，生成 partial 收 1，补全是新收费操作。
5. **存在：截止对象。** 旧稿混用活动 deadline 和运行上限。v2 用活动制作完成 deadline、UTC 当前时间和独立累计活跃运行上限，避免重复计时。
6. **部分成立：失败计费。** 旧稿免费工具下不存在漏收费，但没有可执行的收费扩展。v2 给成功、部分、明确失败、未知结果和重放统一规则。

## 二、状态与一致性

7. **存在：双存储协调。** 不要求两库强行共用事务。v2 规定业务库权威、checkpoint 投影、操作 receipt 重放、revision 对账和不一致终态。
8. **部分成立：恢复审计。** 旧稿提过 started/receipt 对账，但没列完整故障窗口。v2 给出意图前后、结算前后、checkpoint 损坏与未知结果的处理。
9. **存在：被替代费用与状态。** v2 保留执行事实，用 superseded_by 表示计划关联变化；费用永不因替代删除，产物不自动回收。
10. **原表述不成立：单 current_plan。** 旧稿明确单 Agent、顺序执行，并已有 plan_history；不支持多候选并行不是当前缺陷。v2 保存不可变候选表，支持顺序比较，仍不支持并行。
11. **存在：幂等参数。** 旧稿只有 canonical_args_hash 名称。v2 定义语义字段、规范化、集合/有序字段区别、未知字段拒绝及随机元数据排除。
12. **部分成立：并发。** 单进程运行定位不等于防住第二个 CLI。v2 所有写命令使用同一 OS 全局 worker 锁，明确拒绝并发；暂不设计多租户调度。

## 三、模型与动态决策

13. **存在：原始约束守卫。** v2 不可变 topic_id、允许形式、必需点、素材归属与完整性检查；只承诺合成主题库内的有限校验，不宣称开放文本质量完全可判。
14. **部分成立：无进展。** 旧稿第 5.5 节提过重复动作检测，但详细设计没定阈值。v2 同状态同动作两次无进展停止，识别无新观察的规格往返循环。
15. **部分成立：决策依据。** reason_summary 单独不能证明因果；也不应验证模型内部思维。v2 保存真实请求/响应关联，做观察对照试验、实际复现和代码审查。
16. **部分成立：纠错。** 旧稿 11.4 已明确纠正计入轮数，因此“未明确计入”不成立；连续次数/耗尽状态确实缺。v2 连续两次非法动作停止，合法动作重置连续计数。
17. **部分成立：替代偏好。** 题目未要求最优解，不能把“没定义全局优化”当漏项。v2 补足默认目标次序、硬约束和防循环，不强迫穷举所有候选。
18. **部分成立：注入防护。** 旧稿已有预算、依赖、保存守卫，输入注入并不能直接绕过这些程序检查；但角色隔离和主题约束不足。v2 定义不可信数据、白名单和不可变字段，并承认语义风险余量。

## 四、工具执行

19. **存在：错误映射主体。** v2 由 ToolAdapter/执行器归一错误，不让模型或任意工具响应自行决定可重试；未知异常默认不重试。
20. **部分成立：参数校验。** 旧稿写过格式、依赖、状态、有效产物及版本校验，不是完全缺失；工具级 ID/枚举/归属校验和统一错误协议确实没落实。v2 明确三层校验。
21. **部分成立：保存粒度。** 旧稿 11.5 明确“产物存在且有效”，不是仅宏观条件；但有效性的业务定义缺少。v2 检查非空必需段、内容哈希、task 归属和 partial 禁用。
22. **部分成立：旧估算。** v1 已禁止跨版本使用旧报价，但允许参数原地变更的边界未封闭。v2 不可变 spec_hash、script_hash、规则版本绑定，并重新计算费用/时间可行性。
23. **原表述不成立：自动回滚。** 本题允许保留成功结果，也未要求撤销已生成内容；后续失败不应抹掉历史或退款。v2 定义本地产物保留、费用不退、无真实发布。未来外部发布需另设计补偿事务。

## 五、测试与证据

24. **原表述不成立：替身必须与真实模型一致。** 两者职责不同，不要求动作分布一致；旧稿已要求真实模型路径。风险在于只跑替身却宣称模型通过。v2 分开协议测试与真实模型实验，全部结果如实记录。
25. **部分成立：异常覆盖。** 旧矩阵已包含保存数据库失败、非法动作和真实模型失败路径，不是只有工具故障；模型协议异常、账本损坏与关键崩溃窗口未覆盖。v2 评估计划补入这些用例。
26. **原表述不成立：不同 request_id。** 旧稿 11.7 已写有意新建使用新 ID；相同输入可代表合法新任务，不应无条件合并。v2 明确规范化输入冲突和有意重新生成。
27. **原表述不成立：续跑完全未定义。** 旧稿 11.7 已分中断恢复和 incomplete 后新 run，矩阵也有跨 run 测试。v2 进一步规定 thread/run 和验收步骤，防止把自动重试冒充续跑。
28. **部分成立：费用分项测试。** 设计已有分项返回，但测试没列分项归属/触发条件。v2 测活动分项、attempt 收费、规则版本、沉没成本和唯一 charge。
29. **部分成立：Trace 防伪。** 与 15 相关。普通本地 Trace 本来不能防提交者伪造，不是加 reason 或哈希就能解决；考核要求可复现与模型动作证据，并未要求密码学自证。v2 明示证据限度。
30. **存在：真实时间覆盖。** 固定时钟只能测规则。v2 增加真实延迟、超时取消、退避时间和截止前后保存边界测试。

## 六、范围与长期演进

31. **存在：上下文预算。** 总步数上限不能控制单次结果大小。v2 固定上下文结构、有限摘要、完整产物外存、token 预检与 CONTEXT_LIMIT。
32. **存在：规则版本。** v2 固定每个 task 的资料/工具/费率/定价/schema 版本；旧版本缺失就拒绝恢复，不静默修改旧账本。
33. **部分成立：多任务资源。** 旧稿已有总运行时间上限，不是完全缺失；多任务配额并非当前单 runner 目标。v2 明确串行锁和累计活跃额度，不宣称支持多任务服务。
34. **原表述不成立：保存后回滚。** 题目不要求版本管理产品。v2 历史只读查询，有意重生成创建关联新任务；首版不回滚已保存方案。
35. **部分成立：约束变更。** 不是必须原地修改 State；旧稿已有输入变更冲突原则。v2 明确预算/deadline 变更建立新任务，模型不可修改，避免热更新扩大范围。
36. **部分成立：合规。** 首版合成资料可以限制主题、允许用途与来源标记，但无法证明真实版权；题目没要求真实网络素材审核。v2 加入合成主题与素材许可规则的有限检查，声明真实法律/内容审核未覆盖。

## 本轮新增发现

- 旧图把“约束不满足”直接通向结束，可能让超预算结果无法回到模型；v2 明确区分方案不可行与任务运行硬上限。
- 旧图在工具节点之后另行 record_result，留下“副作用已发生、权威记录未写”的窗口；v2 把结果、费用、状态与事件纳入业务事务。
- 旧版 plan_hash 设计容易让脚本依赖自己，v2 区分生成前规格与脚本绑定后报价规格。
- 活动可行性不只依赖版本：新增工具费用、真实时间前进也会使旧报价失效，保存必须实时复核。
- 模型 SDK、tenacity 和图重试叠加可能放大调用数；v2 仅保留一个技术重试层。

## 优先级

实施前必须冻结业务口径、指纹规则、工具协议、错误与状态机；代码阶段优先验证费用分项、保存守卫、幂等和真实模型反馈循环。

checkpoint 故障恢复和同 task 第二次运行必须在实际版本上测试。并行、多租户、自动合规判断、外部副作用补偿和历史回滚留作明确后续范围，不以增加复杂度替代核心验收。
