# AI 辅助使用说明

更新：2026-11-06。

## 1. 使用范围

本项目使用 AI 协助完成需求拆解、技术方案比较、数据结构和状态机初稿、测试场景扩展、代码审查以及文档整理。AI 也用于检查实现与考核条款之间是否一致，并根据测试或真实模型运行中的失败提出修改候选。

AI 辅助不等同于把模型输出直接作为正确结果。费用、截止时间、步骤依赖、任务状态和保存条件均由可测试的程序规则决定；真实决策效果通过 DeepSeek 在线 Trace 单独验证，离线 `DemoModel` 和 `ScriptedModel` 只用于验证流程和边界。

## 2. 关键人工判断与修改

提交者对 AI 生成的建议进行了取舍和修改，主要包括：

1. 选择 Python、LangGraph、Pydantic 与 SQLite 的单 Agent 方案，没有为了展示框架引入多 Agent 或界面。
2. 将早期“工具免费”的简化口径改为实际工具费加活动制作报价的总预算，并明确废弃方案已经发生的工具费属于沉没成本。
3. 区分 LangGraph checkpoint 与业务账本：checkpoint 只保存执行进度，SQLite 业务库保存计划、产物、费用、工具回执和最终保存事实。
4. 将模型职责限制为选择动作和替代方案；参数、依赖、预算、截止时间及最终保存由程序守卫校验，避免模型自行宣称成功。
5. 在真实模型首次失败后保留失败证据，修正检索匹配和动作提示，再执行成对预算实验、工具成功/失败对照及强化回归，没有删除不理想运行。
6. 根据审查结果增加完整交付视图，使 CLI 返回计划正文、步骤状态、工具结果、费用分项以及保存结果或未完成原因。

## 3. 验证方式

- 自动化测试：当前执行 `python -m pytest -q -p no:cacheprovider` 为 48 项通过，覆盖规则、仓库、图执行、幂等、失败、额度和恢复边界。
- 离线流程：`examples/` 中保留正常、缺输入、预算重规划、工具失败、无可行方案和重复提交六组输入、输出及事件记录。
- 真实模型：`docs/07-online-evaluation.md` 和 `docs/09-strengthened-online-evaluation.md` 记录 DeepSeek 实际运行、失败、提示修改及最终对照；Trace 中保存供应商、模型、动作、观察引用和 token 用量。
- 人工核对：将 README 命令、文档描述、费用数字、步骤状态与 SQLite 事实进行交叉检查；文档不能替代实际测试或 Trace。

## 4. 边界与披露

- 没有把真实 API 密钥写入代码、示例或文档；本地 `.env` 被忽略，仓库只提供空值 `.env.example`。
- 不提交模型内部思维过程，只记录可审核的动作、工具参数、结果摘要和简要决策依据。
- AI 生成的代码和文字可能有遗漏，因此最终判断以测试、运行结果和人工审查为准。
- DeepSeek 的少量成功样本不能推断稳定成功率；原生 OpenAI 模型入口尚未完成真实调用验证。
