# AI 辅助使用说明

更新：2026-11-06。

## 1. 整体分工

本项目的业务规则、架构选型、图结构设计、测试用例与在线实验均由本人独立完成，AI 主要在代码补全、文字润色和一致性核对环节提供辅助。所有关键判断——包括预算口径、模型与程序的职责边界、checkpoint 与业务账本的分离方案、恢复协议——均由本人提出并编码实现，AI 输出仅作为参考草稿，最终以人工审查和实际测试结果为准。

## 2. 本人独立完成的部分

- **需求与规则**：预算计算口径（工具费+制作报价、沉没成本不退）、12→8 重规划示例、截止时间约束、幂等与不可变版本规则、模型单动作协议、完成定义与验收标准，全部写入 `01-requirements.md`。
- **技术选型与架构**：确定 Python + LangGraph + Pydantic + SQLite 的单 Agent 本地方案，未引入多 Agent、GUI 或并行排程等展示性组件。
- **图结构与节点**：`reconcile / decide / apply` 三节点划分与路由条件，以及早期 guard/context/validate_action 等职责合并方案，由本人设计并在 `runner.py` 落地。
- **状态与恢复协议**：以 `business.sqlite` 为业务事实权威、`checkpoints.sqlite` 仅存执行投影；设计登记意图→纯计算→事务结算→返回图更新的流程，覆盖崩溃窗口、回执重放、checkpoint 缺失重建等场景。
- **守卫与边界**：模型仅负责选择动作，预算、截止时间、费率、工具参数、保存校验全部由程序守卫完成。
- **测试与验证**：48 项 pytest 用例、六组离线场景输入输出、跨进程故障注入与 worker 锁测试、强化回归，均由本人设计并实际运行。
- **在线实验**：DeepSeek 成对预算对照、工具成功/失败对照、同提示词五例回归；首次失败后保留证据并人工修正提示词，未删除不理想运行。
- **文档**：全部评审文档由本人整理，并交叉核对 README 命令、费用数字与 SQLite 实际记录。

## 3. AI 辅助的部分

AI 在本项目中承担以下辅助工作，输出均经人工修改或否决：

- 样板代码与语法补全：Pydantic schema 字段、CLI 参数解析等机械性段落提供初稿，核心逻辑由本人手写。
- 文档文字润色：调整语句通顺度，不改变业务含义与结论。
- 一致性核对建议：提示文档与代码可能存在的偏差，由本人确认后修正。
- 失败排查方向：根据测试报错提供候选修改思路，最终修复方案由本人判断实施。
- 边界用例列举：辅助提示可能遗漏的测试场景，最终取舍与断言由本人确定。

## 4. 验证方式

- 自动化测试：`python -m pytest -q -p no:cacheprovider` 实测 48 项通过，覆盖规则、仓库、图执行、幂等、失败、额度与恢复边界。
- 离线流程：`examples/` 保留正常、缺输入、预算重规划、工具失败、无可行方案、重复提交六组输入、输出及 Trace，全部由运行代码生成。
- 真实模型：`docs/07-online-evaluation.md` 与 `docs/09-strengthened-online-evaluation.md` 记录 DeepSeek 实际运行、失败、提示修改及最终对照。
- 人工核对：README 命令、文档描述、费用数字与 SQLite 事实交叉检查；文档不替代实际测试或 Trace。

## 5. 边界与披露

- 真实 API 密钥未写入代码、示例或文档；`.env` 被 gitignore，仓库仅提供 `.env.example`。
- 不提交模型内部思维过程，只记录可审核的动作、工具参数、结果摘要与简要决策依据。
- AI 生成内容可能存在遗漏，最终以测试、运行结果与人工审查为准。
- DeepSeek 小样本结果不能外推稳定成功率；原生 OpenAI 模型入口尚未完成真实调用验证。
