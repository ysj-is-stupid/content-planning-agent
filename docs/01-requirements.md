# 内容任务规划 Agent：需求与首版规则 v2

更新：2026-11-06。状态：首版业务规格；实施与测试状态见 `04-implementation.md`、`03-evaluation.md` 和 `07-online-evaluation.md`。

本文件与 `02-solution.md` 是后续实施依据；与根目录《技术选型分析.md》的早期建议冲突时，以本版为准。Python + LangGraph 已选定，不再继续比较框架。

## 1. 用户、目标与范围

用户为内容运营人员。输入主题、模拟总预算和活动制作截止时间，Agent 检索合成素材、生成活动脚本、核算方案、保存可执行方案，或者明确说明未完成原因。

首版采用单 Agent、CLI、顺序工具调用、本地合成资料、SQLite、一个真实决策模型，并提供离线模型替身。支持顺序比较多个候选方案，每次只执行一个模型动作。跨进程失败续跑为单独验证的加分能力，不凭配置 saver 就声称完成。

暂不提供界面、部署、多 Agent、并行排程、真实内容发布、支付、多用户并发服务、自动版权判断、任意历史版本回滚。所有这些限制应在最终 README 中公开。

## 2. 输入与不可变约束

必填：`topic`、`budget_units`、`campaign_deadline_at`。预算为非负整数模拟单位；deadline 必须为带时区的 ISO 8601 时间，保存时归一到 UTC，展示时使用输入时区。

可选：`request_id`、`allowed_formats`、`required_points`、`parent_task_id`。首版内容形式仅支持 `video` 和 `image_text`。未指定 allowed_formats 时允许两者；用户明确只要视频时，模型不得擅自改成图文。

合成主题库只覆盖声明的主题及别名。原始 topic 保留；程序解析出不可变 `topic_id`。无法匹配或输入约束不明确时返回 `needs_input` 和缺失/待澄清字段，不随意编造主题。支持范围必须写入样例资料。

缺预算、缺截止时间或缺主题：返回 `needs_input`，无模型调用和收费工具调用。非法金额、非法时区、未知形式：返回 `invalid_input` 错误，不生成方案。零预算有效，但可能无可行方案。已过期 deadline 返回 `incomplete/DEADLINE_EXCEEDED`。

`task_id` 是内部任务 ID；`request_id` 是提交幂等标识。未提供时 CLI 生成并立即展示。原始约束建任务后不可被模型修改。

## 3. 预算口径：包含模拟工具费用

本版明确替代先前“工具全免费、活动预算单独约束”的建议。只实现一种预算口径：

```text
已发生模拟工具费用 = 当前任务所有已结算收费事件之和
待执行工具最高费用 = 本次调用可能发生的最大收费
当前完成总成本 = 已发生模拟工具费用 + 当前活动方案制作报价
允许发起工具 = 已发生模拟工具费用 + 待执行工具最高费用 <= 总预算
允许保存 = 已发生模拟工具费用 + 当前活动方案制作报价 <= 总预算
```

活动制作尚未实际执行，因此报价不是已经扣款；两个候选报价不能相加。被替代方案已经发生的工具费用属于沉没成本，继续占用当前任务预算，不退款。

费用表 r1：检索成功（包括零结果、部分结果）收费 1；生成完整或部分脚本收费 1；估算和保存收费 0；明确失败、参数拒绝和未执行调用均收费 0。所有费用为整数，任何失败原因和费用由执行器按版本规则结算。

同一幂等操作的技术重试在明确失败时收费 0，最后一次成功或部分成功结算 1 次。重放已完成操作读取已有结果，不再次收费。模型决定新建不同脚本、补全脚本或改变检索条件，是新操作，按表收费。不能以重用步骤名称避免计费。

模型供应商的真实 API 账单不混入模拟单位；记录可取得的 token 用量，未测量金额标为 `not_measured`，不能填零。本项目只证明模拟费用规则，不宣称满足真实货币预算。

## 4. 报价规则与 12 → 8 示例

合成制作报价 r1：video 基础成本 8、素材授权 2，总计 10，预计制作 120 分钟；image_text 基础成本 4、素材授权 1，总计 5，预计制作 45 分钟。授权费属于尚未发生的活动制作报价。

预算 10 时，检索费 1 + 视频脚本费 1 + 视频制作报价 10 = 12。模型观察报价后改成图文，再支付脚本生成费 1，复用同一有效检索结果：累计工具费 3 + 图文报价 5 = 8。这个 8 包含废弃视频脚本已经产生的费用。

估算工具同时返回分项、活动报价、已发生工具费、完成总成本、预算缺口和耗时。超预算是“估算成功，但方案不可行”，不伪装成工具运行异常。

示例仅为设计推演。真实模型可能一开始就选图文；不能将预设动作当成真实重规划。预算反应测试从已持久化的视频候选开始，分别给真实模型观察足够和不足的预算结果，诚实标注测试起点。

## 5. 截止时间与运行上限

`campaign_deadline_at` 约束活动制作完成时间。Agent 本身的真实运行会让当前时间前进，故自然占用截止前的可用时间。工具运行时间不再额外重复相加。

```text
预计活动完成时间 = 保存校验时当前 UTC 时间 + 尚未开始的活动制作时长
可行 = 预计活动完成时间 <= campaign_deadline_at
```

生成脚本是规划工具，45/120 分钟是尚未执行的合成制作工时，二者不是同一时间。没有并行制作或资源调度假设。

另设独立的任务累计活跃运行上限 `max_active_runtime_seconds=180`，不与活动 deadline 共用字段名。使用 monotonic 时钟限制运行；跨进程续跑保留已消耗额度，等待用户再次启动的间隔不计活跃额度，但会影响活动 deadline。模型请求默认最多 30 秒、单个本地工具最多 5 秒，均受剩余额度约束。

测试同时提供固定时钟规则测试与真实延迟/超时集成测试，不能仅依靠假时钟声称运行超时已验证。

## 6. 计划、版本与产物

所有影响活动内容、报价或耗时的规范化字段改变，均创建不可变新版本；不使用“调整幅度较小”作为复用判断。字段包括主题、内容形式、渠道、素材版本、脚本规格、数量、长度和生成策略。备注与显示名称单独保存，不影响版本。

素材结果、脚本和报价均保存依赖指纹与内容哈希。复用条件为相关字段、资料版本、规则版本和内容哈希全部匹配。未实现细粒度兼容判断时，选择重新生成或估算。

部分脚本保存为 `partial`，可用于继续生成；首版仅 `complete` 且必需段落均非空的脚本可估算并保存。部分生成收费 1；补全收费 1；补全后形成完整新产物，原部分产物保留。

被替代步骤的执行历史仍是成功或失败；另设 `superseded_by` 表示不再服务当前计划，不将既有成功事实覆盖成失败。产物使用资格单独为 `partial/complete/invalid`；旧版关联不意味着可以引用到新版。任务结束前不自动删除产物。

## 7. 重复执行、失败和续跑

- 相同 request_id、相同规范化输入：返回或继续同一任务；已完成时返回原方案及“此前保存时满足约束”，不伪装成重新校验后的新方案。
- 相同 request_id、不同输入：返回 `REQUEST_CONFLICT`。
- 不同 request_id、相同输入：视为用户发起的新任务。可提示存在同输入任务，但不合并、不复制其费用，也不宣称这是调用重试。
- 有意重新生成或改变预算/截止时间：新 request_id，可带 parent_task_id；首版不提供任务内修改约束和跨任务产物复用。
- 技术重试：同一操作内安全重试，不等同失败续跑。
- 中断恢复：同一次 run 的未完成图从 checkpoint 继续，先检查业务账本。
- 失败续跑：已返回 incomplete 的任务，由显式 resume 入口创建新 run，沿用约束、有效产物、累计工具费和剩余额度；已完成任务不通过 resume 重新生成。

瞬时错误可在幂等前提下最多尝试 3 次，含首次。永久错误、业务不可行和部分成功返回模型。错误类型由工具适配层与执行器统一判定。

## 8. 动态决策与完成定义

模型每轮只能选择一个业务动作：create/revise/select plan、检索、生成/补全、估算、保存或停止。它可选择已知可用形式和素材，但不能修改预算、截止时间、费率表、数据库状态或计数器。

预算与时间可行、主题与用户硬约束保持、脚本完整、产物与报价匹配、数据库保存事务提交成功，才报告 `completed`。保存失败、工具错误、无方案、调用上限、模型不可用等返回 `incomplete`、明确原因、已完成结果和费用。

未知故障不得笼统宣称无可行方案。只有搜索空间完整且穷尽时才能报告已知最低缺口；否则只能说当前候选中未找到。

## 9. 验收与证据

必须覆盖正常完成、缺预算/截止时间、工具失败、预算超限、重复执行；并验证部分成功、不可行停止、真实超时、旧报价拒绝、保存失败及调用上限。

至少提交 3 组实际输入、实际输出与 Trace，覆盖正常、信息/资料不足、工具失败。另需真实模型至少两条不同工具观察导致的不同动作路径。预算路径与工具故障路径均不得由执行器硬编码策略。

离线替身验证费用、状态与执行边界；真实模型集成测试验证动作适应性。两者无需动作完全一致，必须遵守同一协议和不变量。reason_summary 是动作说明，不是因果证明，更不是内部思维过程。

Trace 保存模型请求/响应的脱敏原文或必要协议片段、工具调用、结果、方案指纹、费用事件、状态变化、版本和时间关联。可复现代码、实际运行和成对观察实验提高可信度；本地日志不能提供对提交者的密码学防伪保证。

成功标准最终以可执行测试、实际模型运行和提交材料核验。离线测试与小样本真实模型对照已运行；未验证边界列于 `07-online-evaluation.md`。
