# 在线评估：DeepSeek 真实模型

执行日期：2026-11-06（Asia/Shanghai）。模型：`.env` 中配置的 `deepseek-chat`，经 OpenAI Python SDK 的 Chat Completions 接口调用。密钥只从本机 `.env` 读取，没有写入输入、输出或 Trace。API 返回的 request ID 与 token 用量保存在 `model_decision` 事件中；真实货币账单未测量。

本报告保留当时的在线运行版本与 19 项离线测试快照。后续强化测试现为 48 项，见 `08-hardening-evaluation.md`；强化版 DeepSeek 在线回归见 `09-strengthened-online-evaluation.md`。

## 方法与证据边界

完整正常用例从原始 JSON 输入启动，模型自行选择检索、方案、脚本、估算与保存。两组成对实验从脚本预置的业务库状态启动；预置动作由 `scripts/run_online_eval.py` 执行，**不算作模型决策**。之后的每一步由真实模型返回 JSON 动作，LangGraph 按动作路由，业务守卫验证并执行。Trace 保存模型响应、观察事件引用、工具结果及保存记录。

预算对照的预置状态均为同一规格的视频方案、完整脚本和报价，区别是预算 10 或 20。工具结果对照均为图文 rich 策略，区别是脚本生成返回永久失败或完整成功。任务 ID、事件 ID 和调用时刻自然不同，不能视为字节完全相同的请求。每种条件仅运行一次，结果说明本次行为，不代表统计成功率或模型内部因果证明。

## 实际运行

- **首次完整正常运行：未完成。** 真实模型两次使用较长中文查询，旧检索实现按整串匹配，均返回空结果；模型随后用空素材列表建方案，被守卫拒绝两次，终止为 `INVALID_ACTION_LIMIT`。该运行 4 次模型决策、供应商返回 5,036 tokens。原始事件保留在 `examples/online/traces/normal-initial-failure.jsonl`。修正点：检索支持主题别名与分词匹配，空结果给出扩大查询提示；提示词明确素材和参数约束。
- **修正后的完整正常运行：完成。** 模型从原始输入完成 6 次决策，工具费 2 + 图文报价 5 = 总额 7；供应商返回 10,899 tokens。Trace：`examples/online/traces/normal-full-success.jsonl`。这是未预置候选的真实模型完整路径。
- **预算不足对照：完成。** 预置视频完成总额为 12，预算 10。模型观察后首个动作是 `revise_plan`，选图文与 compact 策略；随后生成、绑定、估算、保存。最终工具费 3 + 图文报价 5 = 总额 8；5 次模型决策、11,721 tokens。输入、预置说明、输出与 Trace 分别位于 `examples/online/inputs/budget-low.json`、`setups/budget-low.json`、`outputs/budget-low.json`、`traces/budget-low.jsonl`。
- **预算充足对照：完成。** 相同视频规格，预算 20。模型首个动作是 `save_plan`，保留原视频；总额 12，1 次模型决策、2,020 tokens。对应文件使用 `budget-high` 名称。两条预算路径的动作差异由模型响应产生，图未按预算硬编码切换格式。
- **脚本永久失败对照：完成。** 预置 rich 生成明确失败且不收费。模型首个动作 `revise_plan`，改为 compact 策略并选用检索结果中的素材；后续生成、估算、保存。工具费 2 + 图文报价 5 = 总额 7；5 次模型决策、9,839 tokens。对应文件使用 `failure-permanent` 名称。
- **脚本成功对照：完成但有一次无效引用。** 预置 rich 脚本成功。模型首个动作也叫 `revise_plan`，但参数是绑定脚本哈希，与失败对照的改策略不同；它同时自行增加了一份素材，使旧脚本依赖失效。估算守卫返回 `SCRIPT_INELIGIBLE`，模型重新生成后完成。总额 8，5 次决策、10,951 tokens。对应文件使用 `failure-success` 名称。这次错误与额外费用是实际结果，未从证据中剔除。

## 提示修正后的复测

提示词增加了“绑定已有脚本时保持全部生成规格，只新增脚本哈希”；上下文也显示产物是否匹配当前生成规格。复测文件保留在相同目录，名称带 `-retest`。

- 成功结果复测：模型直接绑定原脚本，再估算、保存；3 次决策，总额 7，6,338 tokens，旧脚本得到复用。
- 永久失败复测：模型先重放了失败操作，随后扩大检索，又重放一次失败操作，最终改 compact 策略并完成；8 次决策，总额 8，16,804 tokens。多出的 1 单位来自新增检索，显示模型仍可能低效探索。已完成操作的回执避免重复收费。

本次共记录 **8 个在线运行：7 个完成，1 个未完成**；供应商返回的总用量为 **73,608 tokens**。样本小且中途修正了检索与提示词，不能把 7/8 作为稳定成功率。所有在线输入、预置状态、输出、Trace 和汇总均在 `examples/online/`；`runtime/` 中的业务数据库与 checkpoint 为本地运行产物。`python -m pytest -q` 同期通过 19 项离线测试。

## 仍需补验

当前结果证明本次真实模型确实在预算和工具结果观察后输出了不同参数或动作，且最终方案由守卫真实保存。尚未覆盖同 run 的硬进程崩溃恢复、模型请求未知结果对账、完整 token 上限预检、瞬时错误重试，以及更大样本的稳定性。普通本地 Trace 也不提供防提交者改写的密码学保证。
